# Standalone Grading Workbench

This route family provides the first runnable slice of the standalone React and
PixiJS grading workbench. The current release is read-only: it resolves one
ordinary dual-grading task and displays its secured image. Grade selection,
annotation mutation, and submission are not enabled yet.

## Page route

```http
GET /grading/workbench/task/{task_uuid}/{slot}
```

The page is a standalone HTML application shell. It does not render or include
the legacy `_grading_card.html` partial. The shell loads hashed JavaScript and
CSS from the Vite manifest generated by `npm run build:grading-workbench`.

Allowed roles are `resident`, `ophthalmologist`, and `admin`. A permitted role
is not sufficient by itself: the user must have an active
`UserDiseaseUnitRole` grant for the task's effective disease, lab unit, and
requested slot.

Supported slot values are `resident`, `resident2`, and `arbitrator`.

## Workspace API

```http
GET /api/grading-workbench/workspaces/task/{task_uuid}?slot={slot}
Accept: application/json
```

This authenticated JSON endpoint resolves the task and image from server-side
records. The client cannot select a project, disease, lab unit, or image by
submitting additional identifiers. GET requests do not require a CSRF token.

### Successful response

```json
{
  "schema_version": 1,
  "context_revision": "64-character SHA-256 revision",
  "target": {
    "type": "task",
    "ref": "task-uuid",
    "slot": "resident"
  },
  "task": {
    "uuid": "task-uuid",
    "state": "pending",
    "disease": { "id": 3, "name": "Glaucoma" },
    "lab_unit": { "id": 8, "name": "Glaucoma Lab" }
  },
  "image": {
    "uuid": "image-uuid",
    "source": "encounter_file",
    "url": "/media/img/image-uuid",
    "filename": "fundus.jpg"
  },
  "capabilities": {
    "view": true,
    "annotate": false,
    "submit": false
  },
  "read_only_reasons": [
    "Grading submission is not enabled in this foundation release."
  ]
}
```

`image.source` is one of `encounter_file`, `direct_image`, or
`encounter_set_image`. The image URL remains protected by the normal media
route authorization and rate limits.

Responses include `Cache-Control: no-store, private`.

### Errors

| Status | Error | Meaning |
|---|---|---|
| `400` | `invalid_target` | Missing task reference or unsupported slot |
| `403` | `access_denied` | Role is allowed but the disease/lab/slot grant is absent |
| `404` | `not_found` | Task UUID does not resolve |
| `422` | `image_unavailable` | Task has no concrete image that this viewer can display |

The normal authentication and role decorators may return their standard login
or authorization response before this error envelope is reached.

## Frontend build and verification

```bash
make grading-workbench-test
make grading-workbench-build
```

Production Docker builds compile the frontend in the dedicated
`grading-workbench-builder` stage and copy the manifest and hashed assets into
the web image.
